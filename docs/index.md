# KKP Provider

The KKP provider manages [Kubermatic Kubernetes Platform](https://www.kubermatic.com/products/kubermatic-kubernetes-platform/) (KKP) installations as code with [OpenTofu](https://opentofu.org) or Terraform. It talks to the same REST API as the KKP dashboard.

Use it to declare:

* **Projects** ([`kkp_project`](resources/project.md)), their **members** ([`kkp_project_member`](resources/project_member.md)) and **SSH keys** ([`kkp_ssh_key`](resources/ssh_key.md)).
* **Clusters** ([`kkp_cluster`](resources/cluster.md)) and their worker nodes, **machine deployments** ([`kkp_machine_deployment`](resources/machine_deployment.md)). Supported cloud providers: OpenStack, AWS, Azure, Google Cloud, Hetzner and DigitalOcean.
* **Service accounts** ([`kkp_service_account`](resources/service_account.md)) and their **API tokens** ([`kkp_service_account_token`](resources/service_account_token.md)).

Data sources look up datacenters, Kubernetes versions, projects and clusters, and fetch a cluster's admin kubeconfig for the `kubernetes` and `helm` providers.

## Example Usage

```terraform
terraform {
  required_providers {
    kkp = {
      source = "samualfageme/kkp"
    }
  }
}

# Credentials usually come from the environment:
#   export KKP_HOST=https://kkp.example.com
#   export KKP_TOKEN=<project service account token>
# A service account token names its project, so project_id can be left out.
provider "kkp" {}
```

## Authentication

The provider sends a bearer token with every request. Use a **project service account token**: in the KKP dashboard, open the project, go to *Service Accounts*, add a service account with the *Editor* role and create a token for it. KKP shows the token only once.

| Provider argument | Environment variable |
|-------------------|----------------------|
| `host`            | `KKP_HOST`           |
| `token`           | `KKP_TOKEN`          |
| `token_file`      | `KKP_TOKEN_FILE`     |
| `project_id`      | `KKP_PROJECT_ID`     |
| `ca_certificate`  | `KKP_CA_CERTIFICATE` |
| `insecure_skip_verify` | `KKP_INSECURE_SKIP_VERIFY` |

A service account token belongs to one project, and the provider reads that project from the token. Resources and data sources then default `project_id` to it, so most configurations never set `project_id`.

Things a service account token cannot do, because KKP does not allow them:

* create or delete projects (`kkp_project` needs a user token, for example an OIDC ID token of a project owner or an admin);
* reach other projects;
* change anything when the service account is in the *Viewer* group.

Other tokens the KKP API accepts work too, such as an OIDC ID token, but those expire after minutes or hours.

## Timeouts and waiting

KKP reconciles asynchronously. The provider waits for new projects to become active, for cluster control planes to become healthy (`wait_for_ready`), for machine deployment replicas to become available, and for deletions to finish. KKP refuses machine deployments until the control plane is healthy, so the provider retries their creation until then. Resources with long waits accept a `timeouts` block.

## Schema

### Optional

- `ca_certificate` (String) PEM CA bundle to trust in addition to the system roots. Defaults to `KKP_CA_CERTIFICATE`.
- `host` (String) Base URL of the KKP dashboard/API, e.g. `https://kkp.example.com`. Defaults to the `KKP_HOST` environment variable.
- `insecure_skip_verify` (Boolean) Skip TLS verification. Only for lab installations. Defaults to `KKP_INSECURE_SKIP_VERIFY`.
- `max_retries` (Number) How often a request is retried on rate limiting, gateway errors and network errors. Defaults to 4.
- `project_id` (String) Project used by resources and data sources that leave `project_id` unset. Defaults to `KKP_PROJECT_ID`, then to the project a service account token belongs to (read from the token).
- `token` (String, Sensitive) Bearer token for the KKP API. Normally a project service account token (Project → Service Accounts → Add token). Defaults to `KKP_TOKEN`. Conflicts with `token_file`.
- `token_file` (String) Path to a file holding the token. Defaults to `KKP_TOKEN_FILE`.
